# Концепция: Часть 1 + Часть 2

## Общая картина

```
      Часть 1                        Часть 2
  ┌───────────────┐            ┌──────────────────┐
  │  DnB          │            │  Реестр страны   │
  │  поиск фирм   │  Excel     │  выписка PDF     │
  │  + отсев      │ ─────────► │  + проверка      │
  └───────────────┘  лист по   └──────────────────┘
                     дате
     ↓                              ↓
  фирмы.xlsx                   выписки/<ГЕО>/*.pdf
  (лист 13-07 + Лог)           отчёт: 7 из 10
```

Две **отдельные** программы. Так решено сознательно: отлаживать проще. Автозамена
выпавших фирм (Часть 2 не смогла — Часть 1 добирает новую) появится позже, когда обе
части будут работать по отдельности. Сейчас Часть 2 просто **докладывает**.

Общее у них — ядро: один браузер, одно окно «нужен человек», одни правила именования.

```
common/     браузер, окно паузы, имена файлов   ← общее для обеих частей
part1/      DnB -> отсев -> Excel
part2/      Excel -> реестры 25 стран -> PDF
```

---

## Главный принцип обеих частей: человек в контуре

Сайты — это капчи, логины, попапы и вёрстка, которая меняется без предупреждения.
Закрыть всё это кодом нельзя. Поэтому:

> **Скрипт никогда не гадает и никогда не падает молча. Нужен человек — он останавливается и зовёт человека.**

Браузер запущен видимым. Всплывает окно поверх всех + звук:

```
┌──────────────────────────────────────────┐
│  ТРЕБУЕТСЯ ЧЕЛОВЕК — Нужен вход в систему│
│  DEEP HEAT d.o.o.                        │
│  Сайт AJPES требует авторизацию.         │
│  Залогинься в браузере и нажми           │
│  «Продолжить».                           │
│  [Продолжить] [Пропустить] [Стоп]        │
└──────────────────────────────────────────┘
```

Поводы: капча · логин · неоднозначный матч · попап заблокировал вкладку ·
сайт изменился · элемент не найден.

Профиль браузера постоянный → логин один раз за прогон, а не на каждой фирме.

## Часть 1 — поиск фирм

DnB: поиск по слову → страна → карточки фирм → сайт/имя/адрес/отрасль.
Селекторы взяты из твоего рабочего `scraper.py`.

### Отсев: только жёсткие правила

Ты отверг модель с баллами и «списками на потом» — правильно: при 3000 аккаунтов
в месяц никто их разбирать не будет. Поэтому пять бинарных правил, первое сработавшее
выбрасывает фирму:

| # | правило | зачем |
|---|---|---|
| 1 | нет сайта | без сайта фирма бесполезна |
| 2 | **нет правовой формы в названии** | это ИП/физлицо → нет записи в реестре → Часть 2 никогда не скачает выписку |
| 3 | отрасль в чёрном списке | политика Google Ads |
| 4 | бренд из минус-листа | франшизы и представительства |
| 5 | уже использована | реестр: одна фирма не уходит двум людям |

Всё отсеянное → лист **«Лог»** (имя, отрасль, сайт, причина). Лог не для ежедневного
разбора. Он для того, чтобы раз в неделю прислать его мне и подкрутить правила:
не режем ли лишнего, не пролезает ли мусор.

### Реестр использованных фирм

Интерфейс нарочно узкий — `check(key)` и `record(key)`. Сегодня за ними локальный JSON.
Завтра — SQL или бот `@usedcompaniesarb_bot`: меняется **только класс**, остальной код
не трогаем.

### Excel

Новый лист на каждый прогон, названный датой (`13-07`) + один общий лист «Лог».
Excel запрещает `/` в имени листа — поэтому `13-07`, а не `13/07`.

## Часть 2 — скачивание выписок

Одно ядро + один файл на страну (≈40 строк). Контракт драйвера:

```
search()  →  open()  →  check()  →  fetch()
 найти      открыть   проверить    получить
 фирму      карточку   статус       документ
```

Всё остальное — браузер, матчинг, вызов человека, переименование, отчёт — делает ядро.

### Каскад сопоставления (одинаковый для всех гео)

```
поиск по нашему имени
   ├─ ровно одно точное совпадение ──────────► берём
   ├─ несколько → различаем по АДРЕСУ → одно ► берём
   └─ иначе ──────────────────────────────────► ЗОВЁМ ЧЕЛОВЕКА
```

Смысл один: **никогда не скачать выписку не на ту фирму**.

### Четыре способа получить документ

| способ | как | гео |
|---|---|---|
| **A. Скачивание** | кнопка/ссылка отдаёт файл | CZ, EE, FR, UK, PL, NO, SI, AT, LV, DK, US, FI, AU |
| **B. Печать страницы** | `page.pdf()` = Ctrl+P → «Сохранить как PDF», без диалога | CH, BE, HR, HU, BG |
| **C. Два шага** | сначала номер, потом реестр по номеру | BG (hithorizons → registryagency) |
| **D. Шаблон** | реестр не даёт бесплатный PDF → данные в .docx → PDF | SE, NL |

### Где твой DocDowloader расходится с инструкцией

Разбирал построчно. Источник правды — **инструкция**, код проигрывает:

| гео | DocDowloader делает | инструкция велит | вердикт |
|---|---|---|---|
| **Швейцария** | тянет кантональный PDF с chregister.ch → **упирается в капчу** | напечатать страницу Zefix | **инструкция сильно лучше** — печать капчу обходит целиком |
| **Франция** | DATA INPI PDF + страница Figaro | annuaire-entreprises → «Extrait RNE» | инструкция |
| **Польша** | официальное API Минюста | krs-pobierz.pl | твоё решение: krs-pobierz |
| **Чехия** | `STARTS_WITH` + `PLATNE` + `print-pdf` | то же самое | **совпадает** — эталон |
| **Британия** | `filing-history?category=incorporation` + `a[href*=format=pdf]` | то же самое | совпадает, взял пути себе |

Ещё две вещи из твоего кода я **не** переносил намеренно:
- **рандомизация** (перемешивание выдачи, случайный порядок страниц) — в старом коде она
  нужна была, чтобы набрать N случайных фирм по слову. У нас на входе **конкретный
  список** из Части 1: каждую фирму надо найти именно её. Рандом тут вреден.
- **многопоточность** (`ThreadPoolExecutor`) — несовместима с «человеком в контуре»:
  нельзя звать человека из пяти потоков сразу. Скорость мы меняем на управляемость.
