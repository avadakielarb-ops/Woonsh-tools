# Сценарий: путь заказа во всех вариантах

**Заказ** — «сколько фирм каких стран нужно» (как у владельца: «10 EE + 10 FI + 10 AU», `продолжение.py`).
**Путь заказа:** заказ → поиск → выписки → бот → Google Таблица → взять в работу (папка выдачи + платёжки).

Как проверять:
- **Авто** — прогоняется скриптом `прогон_заказа.py` на НАСТОЯЩЕМ движке Фирм (подменены только DnB, сайты реестров,
  бот, Google Таблица и человек). Последний результат — `ОТЧЁТ_ПРОГОНА.md`, полный лог — `лог_прогона.txt`.
- **Живьём** — только на Windows владельца: настоящий Chrome, профиль, Cloudflare, Telegram, таблица.

Запуск: `python перенос/сценарий_заказа/прогон_заказа.py` (Python 3.12 + openpyxl + playwright; tkinter нужен для импорта окна).
После переноса в Woonsh — указать путь к `woonsh_tools/companies/engine`: `python … прогон_заказа.py woonsh_tools/companies/engine`.
Результат должен остаться тем же или лучше — это и есть приёмка этапов 1–3 из `IMPLEMENTATION.md`.

## 2. Найденные дыры в коде Фирм (НЕ исправлены — код владельца, нужно «да»)

### Дыра №1. «Проверить у бота → из прогона» после поиска по ОДНОЙ стране находит 0 фирм
- Где: `Фирмы/код/проверка_ботом.py` `из_прогона()`: `свой = лист.split(".")[0].upper()`.
- Почему: лист одной страны называется «30-10 EE» и колонки «Гео» в нём нет (`ExcelWriter` пишет «Гео» только в мультилист).
  Страна берётся из имени листа целиком — «30-10 EE», а в поле окна стоит «EE». Совпадений ноль.
- Чем грозит: кнопка «из прогона» для одиночного прогона бесполезна (проверено прогоном). Если поле гео очистить — фирмы найдутся
  (проверено), но с листом «30-10 EE», которого нет в Google Таблице (там лист «EE»); по коду `применить()` правит строки по этому
  листу — значит статусы бота в таблицу, скорее всего, не лягут (прогоном не проверено).
- Предлагаемая правка (1 строка): брать код страны из конца имени листа — `свой = лист.split(".")[0].split()[-1].upper()`.
- В Woonsh: автоматический бот (`bot_auto.py`) это обходит, если брать фирмы из таблицы (`собрать`), а не из книги. Решить при переносе.

### Дыра №2. «Продолжить прерванный» для ОДНОЙ страны перезаказывает всё в новый лист
- Где: `продолжение.py` `сделано()` (`if not iг: return {}`) + `окно.py` `старт(продолжаем=…)` → для одной страны зовётся `run()`,
  который не принимает `лист` и не знает остатка.
- Что видно: (а) заказ по одной стране добран целиком, а кнопка «Продолжить» не исчезает — `сделано()` не видит фирм на листе без «Гео»,
  хотя комментарий в `окно.py:1058` обещает обратное; (б) прервали на 1 из 3 → «Продолжить» завёл лист «30-10 EE (2)» и взял ещё 3:
  **4 фирмы на заказ из 3**, в двух листах. В логе окно при этом пишет «Продолжаю в лист … — фирмы лягут туда же».
- Мультигео работает правильно (лист с «Гео», `run_мультигео(лист=…, сколько_по_гео=…)`).
- Предлагаемая правка: в `старт()` при продолжении всегда идти через `run_мультигео` (как для нескольких стран), либо
  в `сделано()` для листа без «Гео» считать все строки страной из имени листа и передавать `лист` в `run()`.

### Дыра №3. В автономе вписанный список слов используется только первым словом
- Где: `part1/engine.py` `_по_стране()` → `не_добрали()`: при `авто_слова` сразу `сменить_слово_само()` (только запас слов),
  а список «aurora, ice» из поля «Слова» дальше первого слова не читается. В ручном режиме список проходится («Перейти к следующему слову?»).
- Чем грозит: пишешь свои слова, включаешь «Автономно» — программа ищет по первому, а потом по запасу, а не по твоим.
  Если запас пуст — страна закрывается недобранной (в прогоне: 1 из 3), хотя твоё второе слово дало бы фирмы.
- Предлагаемая правка: в `не_добрали()` при `авто_слова` сначала брать следующее слово из вписанного списка, потом запас.

## 4. Что ещё выяснилось при прогоне

- **«Взять в работу» сейчас работает не так, как записано в плане.** В окне владельца (`окно.py:1734`) человек ВСТАВЛЯЕТ платёжки
  фирм, которые уже забрал в таблицу фармера, и программа отмечает их «отработано» и собирает их выписки в папку.
  Владелец в чате просил: «нажимаю, выбираю количество и гео → создаётся папка с N выписками + Excel с платёжками».
  Сценарий проверяет новое поведение: N годных выбираются автоматически, дальше работает НАСТОЯЩИЙ код выдачи
  (`Окно._отметить` → `_собрать_папку`). Новое поведение = новый код в Woonsh (`geo_panel.py`), выдача — код владельца.
- **«Таблица фармера»** — по коду это та таблица, куда фармер вставляет забранные платёжки (`окно.py:1738`).
  Это совпадает со словами владельца «таблица фармера нужна для функций меню».
- **Выписки живут вне папки программы**: путь в `данные/пути.json` (ключ «выписки», у владельца — `Downloads\Выписки`).
  Woonsh должен брать его оттуда же (см. `ОТКУДА_ЧТО_БРАТЬ.md`).
- **Фирма, сменившая имя:** если реестр показывает только новое имя без прежнего — по правилу владельца (20.10: адрес не выбирает
  фирму с другим именем) её решает человек; в автономе — пропуск. Если реестр показывает прежнее имя (как UK) — берётся сама,
  выписка называется новым именем, ячейка платёжки подсвечивается жёлтым. Оба поведения — как задумано.
