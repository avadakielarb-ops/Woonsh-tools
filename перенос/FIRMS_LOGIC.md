## 2. Пункт «Поиск» — интерфейс

```
РЕЖИМ РАБОТЫ:   ◉ Стандартный (поиск + выписки + бот)   ○ Только поиск фирм

ЧТО ИЩЕМ:       ◉ С сайтом   ○ Без сайта
ИСТОЧНИК:       ◉ из найденных на DnB   ○ прямо в реестре выписок     ← строка видна ТОЛЬКО при «Без сайта»

ГЕО:            [▼ одна страна]   ☐ Мультигео → окно выбора стран (как сейчас в Фирмах: список с цифрами)
ЯЗЫК СЛОВ:      [▼ Английский | Региональный | Региональный + английский]   ← ОДНА строка, второго «языка» нет
СЛОВА:          [______________]  (пусто — возьму сам)
СКОЛЬКО НА СТРАНУ: [   10 ]       ← без верхнего предела

☐ 🤖 Автономно (не спрашивать, пропускать)       ← во ВСЕХ режимах
☐ ⚡ Ускоренно (не дочитывать пустые слова)      ← работает только вместе с Автономно (окно.py:939)

[▶ СТАРТ]  [⏭ Продолжить прерванный]  [📖 Пересмотреть слова]  [■ Стоп]

──── Что происходит ───────────── [↻ Повторить последнее действие] ☐ ✋ Ручное управление
  статус-строка: «CZ · слово granite · найдено 4/10 · выписки 2/4 · бот: ждём»
  лог: строки красятся по первому символу (✔ зелёный, ✘ красный, ⚠/⏭ золото, СВОДКА — маджента)

ПРАВАЯ ПАНЕЛЬ «Всё идёт само» — HumanGate: вопрос + крупные кнопки
```

Ничего лишнего: нет «языка поиска» отдельно от «языка ключевых слов», нет выбора провайдера Gemini/Google Search,
нет «проверять сайты через ИИ» (поиск сайтов удалён).

### Автономно ≠ Ручное управление

| | Автономно | Ручное управление |
|---|---|---|
| Что | Программа сама отвечает на свои вопросы: пропускает спорное, берёт слово из запаса | Ты можешь дать команду работающему прогону: Стоп, Пропустить, Повторить, Сменить страну, Продолжить |
| Когда нужно | Ушёл от компьютера | Прогон завис / пошёл не туда |
| Как переключается | НА ХОДУ, `threading.Event` `self.самоход` (окно.py:157, 366). Переключение ещё и «пинает» зависший вопрос | Чекбокс, панель кнопок (окно.py:551, 2247, 2273) |
| Можно оба сразу | да | да |

## 4. Поток работы

### Порядок этапов (ВАЖНО)

```
1 ПОИСК  →  2 ВЫПИСКИ  →  3 БОТ  →  4 ТАБЛИЦА (выгрузка)  →  5 ВЗЯТЬ В РАБОТУ (по кнопке)
```
Бот — ПОСЛЕ выписки: компания могла поменять имя, проверяем по имени из выписки.
В старом окне кнопки «Ход работы» шли «1 Поиск, 2 Проверка у бота, 3 Выписки, 4 Выдача» — переставить.

### 4.1 Перед стартом (проверки)

1. Заполнены настройки: имя фармера, таблица фирм (адрес Apps Script + ключ), ключ Gemini (если слова пустые), Telegram-сессия (если Стандартный режим).
2. Выбрано хотя бы одно гео, количество > 0.
3. Профиль браузера свободен (`common/browser.py` `держат_профиль()` / `освободить_профиль()`).
4. (Вторая волна) Мониторинг: драйвер гео жив.

### 4.2 Этап 1 — слова

- Слова введены → берём их. Пусто → `part1/запас.py` (буфер `запас_слов.json`) → `part1/слова_gemini.py` → встроенный словарь `part1/слова.py`.
- Язык слов — по строке «Язык слов»: английский / язык страны (`ЯЗЫК_ГЕО`) / оба.
- Слово = часть названия фирмы (природа, камни, металлы, птицы…), не отрасль. Стоп-лист Google Ads в 2 уровня (`СТОП_КОРНИ`, `СТОП_СЛОВА`).
- Слово, давшее < 3 фирм, больше не предлагать. Выданное слово помечается сразу.
- «Пересмотреть слова» = окно «Выхлоп по словам» (`окно.py:1560`, `статистика_слов.py`).

### 4.3 Этап 2 — поиск фирм

**С сайтом / Без сайта + из DnB:**
```
DnB (Playwright, part1/dnb.py) → слово + страна → строки выдачи
  → страна выдачи подтверждена по самой выдаче (≥80%), иначе переискать → человек
  → для каждой строки — отсев (part1/filters.py): бренд / отрасль / уже использована
  → карточка ради сайта
  → ЕСТЬ сайт  → лист гео (датированный/мультилист) + бронь 24ч в реестре
  → НЕТ сайта  → лист «Без сайта»
```
**Фирма пишется ВСЕГДА** — режим решает только, что идёт в зачёт «Сколько на страну»:
искали «с сайтом», а фирма без сайта → она всё равно ложится на лист «Без сайта» (и наоборот).

**Без сайта + прямо в реестре:** `part1/из_реестра.py` `искать(гео, слова, сколько, human, …)`
— DnB не открывается, поиск по слову прямо в реестре страны (до 10 страниц на слово).
Работает только там, где `умеет(гео)`.

Набрали «Сколько» → следующая страна. Слова кончились → добор из запаса / Gemini.
Мультигео — обход стран сверху вниз, всё на ОДИН лист с колонкой «Гео» (мультилист).

### 4.4 Этап 3 — выписки (только режим «Стандартный» или кнопка «Докачать»)

`part2/engine.py` + драйвер гео `part2/geos/<страна>.py`:
```
search → open → check → fetch
каскад запросов (полное имя → без формы → 4/3/2/1 слово)
каскад матчинга: точное имя → адрес → карточки (до 5) → человек
check: «здоровый статус» гео; пустой статус = перечитать → спросить человека
fetch: скачивание / новая вкладка / печать CDP / два шага (BG через ЕИК)
выписка → имя фирмы.pdf; номер → колонка I; файл → колонка J
реестр: бронь → ПОДТВЕРЖДЕНИЕ по официальному номеру (навсегда)
не вышло → бронь снимается, строка в не_вышло.xlsx; постоянная причина → «непригодна»
```
Повтор на таймаутах/сети **уже есть** (`part2/engine.py:1271`): после прохода по стране фирмы с тех.ошибкой
повторяются кодом через 4 с, потом человек, потом снова код. Второй слой повторов НЕ добавлять.
Профиль браузера — реальный общий профиль владельца (Cloudflare без него не пускает).
**США:** поиск на DnB по штатам (FL, NY, WA, GA, CT, UT — владелец прописывал); выписки — только Флорида (`usa_florida.py`).

### 4.5 Этап 4 — бот (АВТОМАТИЧЕСКИ)

Сейчас у владельца (`проверка_ботом.py`, `окно.py:1261`): шаг 1 — список имён в буфер/файл, шаг 2 — вставить ответ бота.
**Станет:** то же самое, но без рук — через Telethon от аккаунта владельца в бот `@usedcompaniesarb_bot`.

```
кого спрашиваем: статус «выписка» (НЕ_СПРАШИВАТЬ_БОТА = закрытые + годные)
имя: из выписки, латиницей, БЕЗ правовой формы (иначе «OÜ» ≠ «OU»)
порции по 50 (бот теряет на длинных; тест_порции_боту.py)
ответ → «дубль/уже есть» → статус «отклонена», строка на лист «Недостойные», ФАЙЛ ВЫПИСКИ УДАЛЯЕТСЯ
        прочие          → статус «годная»
нет ответа → повтор через 30 с, потом лог + ручная кнопка
```
Логику разбора ответа брать из `проверка_ботом.py` и `перечитать_ответ_бота.py` (владельца).
Транспорт (Telethon, `conv.send_message`) — из `X-File/company_search.py:390-420` и вход (код/QR/2FA) из `X-File/telegram_auth.py`.

### 4.6 Этап 5 — Google Таблица

Как у владельца сейчас: `common/таблица.py` (Apps Script), **вариант Б** — прогон пишет локально, в конце выгружает пачкой
(`дописать`, `обновить`, `перенести`, `отработать`). Пока прогон идёт, таблица не меняется — это договорённость.

### 4.7 Взять в работу (Гео и выдача)

`окно.py:1734 взять_в_работу()` → `_отметить()` 1803 → `_собрать_папку()` 1893:
```
выбрать гео + количество → взять N «годных»
создать папку в «выдачи/» (пример: «19-10_20-26_UK_48шт»)
ПЕРЕМЕСТИТЬ выписки в папку (не копировать)
Excel с платёжками (+ txt)
статус → «отработано», строка → лист «Отработано» (локально и в таблице)
```

### 4.8 Режим «Только поиск фирм»

Этапы 1–2, стоп. Фирмы в «Гео и выдача» со статусом «найдена». Потом «Докачать выписки» → этапы 3–4–5.
Технически это галочки этапов очереди `очередь.py` (`этапы = {"собрать": True, "выписки": False}`) — этап «сайты» удалить.

## 5. Статусы фирмы (лестница — `common/статусы.py`, не придумывать новых)

```
найдена → выписка → годная → отработано
              ↘ нет выписки  (реестр отказал, фирма жива — остаётся на листе гео)
              ↘ отклонена    (бот: уже есть)        → лист «Недостойные»
              ↘ брак         (форма/ликвидация)     → лист «Недостойные»
              ↘ спорная      (сами не выбрали)
«дубль» — старое написание «отклонена», новые не пишем.
```
Тот же список живёт в `Фирмы/доки/скрипт_таблицы/Код.js` (ФИРМЫ_СТАТУСЫ) — менять синхронно.

## 6. Реестр фирм (`part1/registry.py`)

- **Бронь** по отпечатку (имя + страна + индекс + город), 24 ч. Фирмы без сайта НЕ бронируются (защита — сам лист «Без сайта»).
- **Подтверждение** по официальному номеру (`ключ_номера(страна, номер)`) — навсегда.
- **Непригодные** — не возвращаются в оборот.
- Атомарная запись, 30 снимков в `.реестр_бэкап/`, `РеестрПовреждён` вместо пустого старта.
- Есть заготовка `ServerRegistry` — на будущее (общий реестр команды).
