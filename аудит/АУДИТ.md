## 1. ЦСВ ВАЙТ — ppc_gemini.pyw (8129 строк)
**Статус:** ✅ ПРОВЕРЕНО

### ПОТОКОВЫЕ / API ОПТИМИЗАЦИИ:

**A. Двухрежимная генерация: API + Браузер (CDP)**
1. **API-режим** (`generate_draft`): `urllib.request` к Gemini API с `responseMimeType: "application/json"` + `responseSchema`. Авторемонт (до 3 раз).
2. **Браузер-режим** (`browser_generate`): Gemini через Chrome DevTools Protocol. Самописный WebSocket (0 зависимостей). DOM polling 1.5с, авто-перезагрузка (SILENCE=90с, FROZEN=150с, 3 попытки). `keep_awake()` + anti-throttle flags.

**B. Авто-ротация моделей**: `MODEL_CHAIN` из 4 моделей. При 429 — мгновенно следующая. `RateLimited` различает минутный/дневной лимит. Thread-safe.

**C. Retry с Retry-After**: 5 попыток, слушает `Retry-After` header и `retryDelay`.

**D. Batch queue** (BatchWindow): персистентный буфер (`batch.json`), авторемонт, stall detection, `follow_up=True`, `chat_url` persistence.

### Другие преимущества: валидация контента (бан gambling/casino/pharma/crypto), DKI-aware length check, промпты для агрегаторов, CSV для Google Ads Editor, тема Aurora, 0 внешних зависимостей.

### Детали реализации (КЛЮЧЕВЫЕ ДЛЯ СЛИЯНИЯ):

**_request() (строки 1230–1284):** Центральная HTTP-функция. `urllib.request` (0 зависимостей). 5 попыток. Парсит `Retry-After` header + `retryDelay` из JSON body. Различает коды: 401/403→ключ, 404→модель, 429→RateLimited (с флагом daily), 500-504→retry. `on_wait(short, detail)` callback для UI.

**auto_chain() (строки 1312–1335):** Кэширует цепочку под ключ. `list_models()` (строки 1287–1294) запрашивает Google API, фильтрует generateContent-совместимые. Если API недоступен — пробует цепочку как есть.

**_call_model() (строки 1350–1407):** Обычная модель — прямой вызов. Авто — цикл по цепочке: 429→cooldown (дневной до 08:00 UTC, минутный 60с), 404→удалить из цепочки. Никогда не спит >180с (выбрасывает "дневные лимиты исчерпаны").

**browser_generate() (строки 2017–2254):** CDP WebSocket. Новый чат через JS_NEW_CHAT (кнопка) с fallback на `location.href`. `send_once()` — вставка через JS_INSERT + 15 попыток нажать кнопку. `await_answer()` — poll 1.5с, SILENCE=90с (нет ответа→reload), FROZEN=150с (ответ застыл→reload). 3 попытки с перезагрузкой. `reload_page()` проверяет, не дописалась ли ответ на сервере. `chat_url` persistence — каждый сайт помнит свой чат. JSON repair в том же чате (до 3 раз). `sink["chat"]` сохраняет URL для регенерации.

**BatchWindow (строки 6638+):** Canvas-таблица (не Treeview — нужны вертикальные линии). Два этапа: Заготовка (ввод данных) → Очередь (генерация). `batch.json` persistence. Авторемонт в цикле (while errors + rounds < MAX). `follow_up=True` — только замечания в ТОМ ЖЕ чате (экономия 16KB промпта). Stall detection. Per-row `chat_url` для точного возврата.

### Проблемы: монолит 8129 строк, Chrome-режим хрупкий (DOM-зависимость).

### 3 главных MERGE:

**1. core/gemini.py:** ЦСВ MODEL_CHAIN + RateLimited (thread-safe) + X-File THINK_LADDER + available_models() + woonsh key rotation → единый Gemini клиент.

**2. ads/generator.py:** ЦСВ промпты + JSON Schema + авторемонт + DKI + бан категорий **+ X-File ThreadPoolExecutor(4)** + parse_json_loose + temperature fallback + BUILTIN_NEG 8 языков + policy_issue → параллелизм + качество.

**3. ads/validation.py:** ЦСВ DKI-aware + бан категорий + X-File deterministic check() + review_signature() SHA-256 → полная валидация + ручное подтверждение.
