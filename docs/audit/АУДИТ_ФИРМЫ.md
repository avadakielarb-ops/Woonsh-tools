# АУДИТ: Поиск фирм (Фирмы/)

## АРХИТЕКТУРА

**Два приложения — старое и новое:**
- `app.py` (1762 строки) — старый интерфейс с Notebook (вкладки)
- `окно.py` (2385 строк) — новое единое окно: выбрал линию → гео → количество → слова → СТАРТ

Новое окно — основное. 4 шага: ПОИСК → БОТ → ВЫПИСКИ → ВЫДАЧА. Список гео с живыми счётчиками (с сайтом, без сайта, годных, проверенных, непроверенных). Мультигео: несколько стран из одного листа.

**Структура модулей:**
```
Фирмы/код/
├── окно.py           — главное окно, UI, управление потоком
├── app.py            — старое приложение (может быть legacy)
├── очередь.py        — слово × страна × количество + стадии
├── common/
│   ├── human.py      — HumanGate: спросить человека / автономно
│   ├── browser.py    — браузер (Playwright или CDP)
│   ├── тема.py       — Aurora (#7a34e6, #d6389e, #3b74ed), тёмная тема
│   └── таблица.py    — работа с Excel
├── part1/
│   ├── engine.py     — поиск фирм: искать + проверить страну
│   ├── registry.py   — реестр фирм (бронь/использована)
│   ├── слова_gemini.py — генерация слов через Gemini
│   └── filters.py    — фильтрация результатов
├── part2/
│   ├── engine.py     — скачивание выписок из реестров
│   └── geos/
│       ├── base.py   — ABC: search/open/check/fetch
│       ├── registry.py — 19 гео-драйверов
│       └── cz.py, ch.py, pl.py, ... — по файлу на страну
└── part3/            — поиск сайтов
```

**Поток данных:**
1. DnB (Dun & Bradstreet) — поиск фирм по словам
2. Проверка страны через результаты поиска (ОК/ПУСТО/ЧУЖАЯ)
3. Запись в Excel + бронирование в реестре (24ч TTL)
4. Скачивание выписок из национальных реестров
5. Подтверждение в реестре (по официальному номеру)
6. Проверка у бота → Выдача (папка с выписками + книга платёжек)

## КЛЮЧЕВЫЕ МЕХАНИЗМЫ

### 1. HumanGate (common/human.py, ~400 строк)
Потокобезопасная система «спросить человека»:
- `ask()` — да/нет/пропустить, блокирует рабочий поток через Event
- `menu()` — выбор из вариантов с подсказкой авто-ответа
- `require()` — обязательное действие (логин, капча)
- Ручные команды: стоп, страна, пропустить, обновить, повторить, продолжить
- `_обогатить`: скриншот + диагностика страницы к каждому вопросу
- `сохранить_excel`: retry при PermissionError (файл открыт), до 20 в авто

**Автономный режим через `threading.Event`** — переключается НА ХОДУ:
- Галочка → `self.самоход.set()` / `.clear()`
- Движок проверяет `самоход.is_set()` в момент вопроса
- В авто: спорное пропускается, слово берётся из запаса
- Переключение режима ещё и «пинает» зависший прогон (`_приказать("повторить")`)

### 2. LocalFileRegistry (part1/registry.py)
Два состояния:
- **БРОНЬ** — 24ч TTL, ключ: страна + нормализованное имя + индекс/город
- **ИСПОЛЬЗОВАНА** — постоянно, ключ: страна + официальный номер

30 резервных копий, одна на прогон. `РеестрПовреждён` — громкий крах, не тихий старт с нуля.

### 3. Гео-драйверы (part2/geos/)
ABC `GeoDriver`: `search()` → `open()` → `check()` → `fetch()`
- 19 стран: CZ, CH, NO, HU, SI, AT, PL, DK, UK, EE, FR, BE, HR, LV, AU, US(FL), FI, BG + NL (не трогаем)
- Методы: download / print / template
- `карточка_открыта()`: тройная проверка (драйвер → гео → общий regex)
- `номер()`: regex для извлечения регистрационного номера
- PLAN карта с волнами и статусом верификации (✔/✔?/○/✘)

### 4. Очередь (очередь.py, 284 строки)
- Задание: слово × страна × количество + стадии (собрать/сайты/выписки)
- Фазы: сначала все Part 1 (поиск), потом Part 3 (сайты), потом Part 2 (выписки)
- Состояние в `очередь.json` после каждого шага — защита от крашей
- `Задание.осталось` — сколько добрать после прерывания

### 5. Генерация слов (part1/слова_gemini.py)
- Gemini с цепочкой моделей: 3.5-flash → 2.5 → 3.7 → 3.8
- Категории: камни, деревья, звери, погода, ландшафт — против паттернов
- Фильтрация через `слова.запрещено` (Google Ads compliance)
- 24 гео с маппингом язык/страна

### 6. Система продолжения
- `продолжение.остаток()` — считает по КНИГЕ (Excel), а не по закладке
- Кнопка «Продолжить прерванный» — добирает в тот же лист
- Подпись показывает: где, сколько осталось, какой лист

## ФИШКИ (лучшее)

1. **Автономный режим на ходу** — не «включил и работай», а переключаемый в любой момент. Галочка ещё и «пинает» зависший прогон.

2. **HumanGate с menu(авто=...)** — движок сам говорит, какой ответ безопасен для робота. Нет безопасного — пропускает, а не врёт.

3. **Тройная проверка карточки** — драйвер + гео + общий regex. Не доверяет одному источнику.

4. **Реестр с двумя уровнями** — бронь (временная, по имени) → подтверждение (постоянное, по номеру). Реалистичный жизненный цикл.

5. **30 бэкапов реестра** — одна порча = откатились. `РеестрПовреждён` не молчит.

6. **Фазы очереди** — сначала весь поиск, потом сайты, потом выписки. Логично: не дёргаем реестры пока весь поиск не собран.

7. **Проверка страны по результатам** — не доверяет DnB, проверяет ОК/ПУСТО/ЧУЖАЯ. Чужая — отдельное лечение.

8. **Строка состояния** — одна строка, видно: где мы, сколько из скольких, сколько взято/пропущено. Для часовых прогонов это критично.

9. **Выдача = папка** — выписки переезжают (не копируются!) + книга платёжек рядом. Нет двойников, всё в одном месте.

10. **Ручные команды в любой момент** — не только через панель вопросов, но и через отдельный чекбокс. Для зависших прогонов спасение.

## СЛАБЫЕ МЕСТА

1. **Монолит `окно.py` — 2385 строк.** UI, логика, поток, очередь, выдача — всё в одном файле. Тяжело навигировать.

2. **Кириллица в идентификаторах** — `самоход`, `очередь`, `выбранные_гео()`, `скачать_выписки()`. Работает, но grep/поиск сложнее, IDE хуже автокомплитит.

3. **Два приложения** — `app.py` и `окно.py`. Если `app.py` — легаси, он сбивает с толку. Если нет — непонятно, когда какое.

4. **DPAPI шифрование** — только Windows. На другой ОС не работает (не критично, если целевая ОС — Windows).

5. **Жёсткая привязка к DnB** — один источник поиска. Если DnB меняет UI или блокирует — всё стоит.

6. **Excel как база** — таблица, листы, колонки по имени. Один кривой лист ломает всё. Нет схемы, нет миграций.

7. **19 гео-драйверов — 19 потенциальных поломок.** Каждый реестр может сменить вёрстку. Нет мониторинга «этот драйвер сломался».

8. **Нет retry на уровне сети** — если реестр не ответил, это сразу «не смог». Для массового прогона неоптимально.

9. **Нет метрик** — сколько фирм в минуту, какой процент пропусков, какие гео проблемные. Только лог.

## СРАВНЕНИЕ С КОЛЛЕГОЙ (X-File)

**У коллеги НЕТ модуля поиска фирм.** Сравнивать напрямую нечего.

Из общих подходов, которые стоит отметить:
- **Коллега использует web-интерфейс** (localhost:8765) вместо tkinter. Плюс: работает из любого браузера, легче стилизовать. Минус: нужен сервер.
- **ThreadPoolExecutor** у коллеги — параллельность из коробки. У тебя — один поток + Event. Для поиска фирм параллельность опасна (реестры блокируют), но для обработки результатов могла бы помочь.
- **Модульность** у коллеги лучше: ads_generator/ (1056 строк) + 5 мелких модулей vs твой окно.py (2385 строк монолит).
